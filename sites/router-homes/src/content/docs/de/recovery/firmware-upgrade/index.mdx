## Ein Upgrade ist nicht nur „die Firmware-Datei austauschen“

Trennen Sie vier Dinge:

1. wurde die **Firmware** geflasht und gebootet;
2. wurde die **Konfiguration** behalten/wiederhergestellt;
3. sind **Pakete/Plugins** noch vorhanden oder müssen neu installiert werden;
4. haben sich **Verwaltung/DNS/WAN** erholt.

Das Behalten der Konfiguration behält keine Pakete. Das Behalten der Konfiguration einer App behält nicht deren Binärdatei.

## Vor dem Upgrade

<Step where="router-shell" title="Release, Target, Paketliste und Backup erfassen" expected="Sie können zurückrollen und wissen, was verschwunden ist.">

```sh
cat /etc/openwrt_release
cat /etc/apk/arch 2>/dev/null
apk list --installed > /tmp/packages-$(date +%F).txt
wc -l /tmp/packages-$(date +%F).txt
sysupgrade -b /tmp/pre-upgrade-$(date +%F).tar.gz
sha256sum /tmp/pre-upgrade-$(date +%F).tar.gz
```

Kopieren Sie das Konfigurationsarchiv vom Gerät; bei einer VM erstellen Sie zusätzlich einen PVE-Snapshot bzw. ein Backup. Lassen Sie es nicht nur in `/tmp`.

</Step>

<Step where="router-shell" title="Image und Prüfsumme verifizieren" expected="Das Image passt zu Release/Target/Architektur und die Prüfsumme ist gültig.">

```sh
wget -O /tmp/openwrt.img.gz <official-image-url>
sha256sum /tmp/openwrt.img.gz
# compare with the matching line in official sha256sums
gzip -dkf /tmp/openwrt.img.gz
ls -lh /tmp/openwrt.img
```

Dieses Labor verwendete das kombinierte ext4-Image 25.12.6 x86/64; die SHA-256 der `.img.gz` stimmte überein, danach wurde es für `sysupgrade` entpackt.

</Step>

<Step where="router-shell" title="Konsole und Rollback bereithalten" expected="Sie können sich von einem unterbrochenen/fehlgeschlagenen Upgrade erholen.">

- Physisches Gerät: seriell/HDMI, Failsafe-Taste, alte Firmware;
- PVE: Snapshot vor dem Upgrade, `qm rollback` prüfen;
- LAN-IP, DHCP, WAN, DNS und Verwaltungsport notieren;
- Trennen Sie während des Upgrades weder den Strom noch entfernen Sie Platten.

</Step>

## Upgrade-Befehl

Standard (Konfiguration behalten):

```sh
sysupgrade -v /tmp/openwrt.img
```

Optionen:

- `-n`: Konfiguration nicht behalten (saubere Installation);
- `-f <backup.tar.gz>`: Konfiguration während des Upgrades wiederherstellen;
- `-c`/`-o`: mehr geänderte Dateien erhalten; komplexere Grenzen;
- Verwenden Sie `-F` nicht, um die Kompatibilität zu ignorieren, es sei denn, Sie verstehen die Folgen vollständig.

Das Upgrade beendet SSH-/Web-Sitzungen; warten Sie den Neustart ab und schalten Sie nicht aus, nur weil die Verbindung abbrach.

## Nach dem Upgrade prüfen

<Step where="client" title="Verwaltungszugang" expected="LAN-IP, HTTP und SSH mindestens einmal prüfen.">

```sh
ping -c 2 192.168.1.2
curl -sSI --max-time 5 http://192.168.1.2/ | head -3
ssh root@192.168.1.2 'cat /etc/openwrt_release'
```

Dieses Labor behielt das LAN `192.168.1.2/24`; HTTP 200 und SSH funktionierten.

</Step>

<Step where="router-shell" title="Konfiguration und DNS/WAN" expected="Die Konfiguration blieb erhalten und DNS/WAN funktionieren tatsächlich.">

```sh
uci show network.lan.ipaddr
uci show dhcp.lan
ip route
nslookup openwrt.org 127.0.0.1
logread | grep -Ei 'dnsmasq|netifd|dhcp' | tail -30
```

In diesem Labor: DNS und HTTP funktionierten nach dem Upgrade; die WAN-Konfiguration blieb erhalten. Prüfen Sie trotzdem erneut die DHCP-Leases der Clients und echtes Internet, nicht nur den Router selbst.

</Step>

<Step where="router-shell" title="Pakete und Plugins" expected="Sie wissen, was verloren ging, und installieren anhand der Liste neu.">

```sh
apk list --installed | wc -l
for p in sqm-scripts luci-app-sqm luci-app-openclash; do
  apk info -e "$p" && echo "$p installed" || echo "$p MISSING"
done
```

In diesem Labor: vorher 239 Pakete, nachher 182; `sqm-scripts`, `luci-app-sqm` und `luci-app-openclash` waren alle weg. Die Konfiguration kann erhalten bleiben, aber die Binärdateien müssen neu installiert werden.

Einzeln neu installieren:

```sh
apk update
apk add sqm-scripts luci-app-sqm
# verify menu/service before the next package
```

Stellen Sie nicht alle Plugins auf einmal wieder her; bringen Sie zuerst Verwaltung/DNS/Grundnetzwerk in Ordnung.

</Step>

## Reihenfolge des Wiederaufbaus

1. Grundnetzwerk: network/dhcp/firewall;
2. DNS: dnsmasq, danach bei Bedarf AGH;
3. Verwaltung: luci/uhttpd;
4. Proxy/Traffic-Shaping: OpenClash, SQM;
5. Zuletzt: Regeln/Abonnements/Performance-Tuning.

Prüfen Sie bei jedem Paket:

- installiert oder nicht;
- LuCI-Menü/Controller vorhanden;
- Dienst startet;
- DNS/Default-Route wurde nicht verändert;
- Deaktivieren stellt das Grundnetzwerk wieder her.

## Rollback

- Physisches Gerät: alte Firmware/Recovery-Modus bereithalten;
- PVE: Snapshot/`vzdump` vor dem Upgrade, bei Fehlschlag die gesamte VM zurückrollen;
- Konfiguration: das Archiv mit `sysupgrade -r` einspielen;
- Verwenden Sie nicht „erneut flashen“ anstelle einer Diagnose des Fehlers.

Dieses Labor verwendete den Snapshot `pre-019`; nach der Aufzeichnung der Ergebnisse wurde auf den Zustand vor dem Upgrade zurückgerollt. Die Seite dokumentiert den tatsächlichen Upgrade-Lauf.
