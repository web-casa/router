## In einem Satz

25.12 hebt alle Targets von Linux 6.6 auf 6.12 und aktualisiert die Toolchain, daher lassen sich für 24.10 gebaute Kernelmodule unter 25.12 nicht laden.

## Versionen im Vergleich

| Komponente | 24.10.0 | 25.12.0 |
|---|---|---|
| Linux-Kernel | 6.6.73 | 6.12.71 |
| GCC | 13.3.0 | 14.3.0 |
| binutils | 2.42 | 2.44 |
| musl | 1.2.5 | 1.2.5 |
| glibc | 2.38 | 2.41 |

25.12.6 hebt den Kernel auf 6.12.112. In 25.12.0 stammt der WLAN-Stack (cfg80211/mac80211) aus Kernel 6.18.7, zusammen mit dnsmasq 2.91, dropbear 2025.89 und busybox 1.37.0.

## Warum das zu Hause wichtig ist

- `kmod-*`-Pakete werden für genau einen Kernel gebaut. Der Feed-Pfad enthält den Kernel-Hash, etwa `targets/<target>/kmods/<kernel-hash>/`, und er muss zum laufenden Kernel passen.
- Ein kmod aus einem anderen Release, einem anderen Build oder von einem Mirror mit anderem Hash lässt sich nicht installieren oder laden. Das ist ein häufiger Grund, warum sich ein Paket „nicht installieren lässt“.
- Builds von Drittanbietern liefern oft ihren eigenen Kernel mit. Offizielle kmods passen dazu womöglich gar nicht.

## Auf dem eigenen Router ansehen

```sh
uname -r
grep -E 'RELEASE|TARGET' /etc/openwrt_release
```
