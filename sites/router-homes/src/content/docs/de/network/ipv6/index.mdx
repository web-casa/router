## Fünf Begriffe zu Adressen und Mechanismen

| Name | Beispiel/Rolle | Häufiger Fehler |
|---|---|---|
| link-local | `fe80::/10` | jede Netzwerkkarte hat eine; nicht öffentlich |
| ULA | innerhalb von `fd00::/8` | im Internet nicht direkt routbar |
| GUA | `2000::/3`, öffentliche Adresse | benötigt PD/Zuteilung vom Upstream |
| RA | Router kündigt Präfix/Gateway/DNS an | kein RA → kein SLAAC |
| SLAAC | Client erzeugt eine Adresse aus dem RA-Präfix | nicht DHCPv6 |
| DHCPv6 | Server vergibt Adresse/Präfix/DNS | anders als IPv4-DHCP |
| PD | Upstream delegiert ein Präfix an den Router | kein PD → kein LAN-GUA |

## Aktueller Zustand

<Step where="router-shell" title="Adressen, Routen und UCI prüfen" expected="Sie wissen, ob Sie nur Link-Local, ULA oder GUA haben.">

```sh
ip -6 addr show
ip -6 route
uci show network.lan
uci show dhcp.lan
uci show network.globals
logread -e odhcpd | tail -30
```

Im Test: `br-lan` hatte die ULA `fd2f:385b:7d0a::1/60` und Link-Local; keine IPv6-Standardroute und keine GUA.

</Step>

## LAN: ULA + RA/SLAAC

<Step where="router-shell" title="LAN-Präfix und RA-Dienst bestätigen" expected="Das LAN hat ein ULA-Präfix und odhcpd sendet RA.">

```sh
uci show network.globals.ula_prefix
uci show network.lan.ip6assign
uci show dhcp.lan.ra
uci show dhcp.lan.ra_slaac
uci show dhcp.lan.dhcpv6
ps | grep [o]dhcpd
```

Im Test:

```text
network.globals.ula_prefix='fd2f:385b:7d0a::/48'
network.lan.ip6assign='60'
dhcp.lan.ra='server'
dhcp.lan.ra_slaac='1'
dhcp.lan.dhcpv6='server'
```

`ip6assign='60'` entnimmt der ULA-`/48` ein `/60` für das LAN; Clients erhalten üblicherweise ein `/64`.

</Step>

<Step where="client" title="Einen Client eine Adresse per RA beziehen lassen" expected="Der Client erhält eine ULA und kann die IPv6-Adresse des Routers pingen.">

Linux-Beispiel (`accept_ra=2` nur in diesem netns; normale Clients behalten üblicherweise die Standardwerte):

```sh
sysctl -w net.ipv6.conf.eth0.accept_ra=2
ip -6 addr show eth0
ip -6 route
ping -6 -c 2 <router-ULA>
```

Der netns-Client im Test erhielt:

```text
fd2f:385b:7d0a:0:5088:71ff:fed4:32d2/64  scope global dynamic
fe80::5088:71ff:fed4:32d2/64             scope link
```

und pingte `fd2f:385b:7d0a::1`. Der Client hatte nur `fd2f:385b:7d0a::/64`, keine IPv6-Standardroute (kein Upstream).

</Step>

## WAN: GUA und PD

<Step where="router-shell" title="Prüfen, ob WAN6/Upstream ein Präfix liefert" expected="Eine GUA und Standardroute, oder ein eindeutiges „kein IPv6“ vom Upstream.">

```sh
uci show network.wan6 2>/dev/null
ubus call network.interface.wan6 status 2>/dev/null
ip -6 route
ip -6 addr show eth1
logread | grep -Ei 'odhcp6c|dhcpv6|pd' | tail -30
```

Typischer Hauptrouter:

```sh
uci set network.wan6=interface
uci set network.wan6.device='eth1'
uci set network.wan6.proto='dhcpv6'
uci commit network
/etc/init.d/network reload
```

- Der Upstream muss IPv6/PD unterstützen; manche ONTs/Provider liefern nur ein `/64` oder nichts;
- ohne PD erfinden Sie im LAN kein „öffentliches Präfix“;
- in diesem Test gab es kein Upstream-IPv6, daher wurden GUA/PD nicht geprüft; nur ULA/RA/SLAAC.

</Step>

## DNS und Firewall

<Step where="router-shell" title="AAAA und IPv6-DNS getrennt testen" expected="Sie wissen, ob es „kein AAAA“ ist oder „DNS nutzte kein IPv6“.">

```sh
nslookup -type=AAAA openwrt.org 127.0.0.1
nslookup -type=AAAA openwrt.org <router-ULA>
cat /tmp/resolv.conf.d/resolv.conf.auto
```

- AAAA kann auch aufgelöst werden, wenn DNS über IPv4 läuft;
- das Client-DNS kann aus RA/DHCPv6 oder manueller Konfiguration stammen;
- stellen Sie nicht das gesamte DNS auf IPv6 um, nur weil „IPv6 funktioniert“; behalten Sie den Fallback auf IPv4/IPv6.

Firewall:

```sh
uci show firewall
nft list ruleset 2>/dev/null | head -80
```

- Erlauben Sie ICMPv6/ND/RA (sonst funktioniert IPv6 nicht);
- erlauben Sie die IPv6-Weiterleitung von LAN zu WAN;
- deaktivieren Sie die IPv6-Firewall nicht, „um die Konnektivität zu testen“; das setzt das LAN der Außenwelt aus.

</Step>

## Häufige Fehler

### Nur fe80-Adressen

- das LAN hat kein ULA-Präfix/`ip6assign`;
- odhcpd läuft nicht / RA ist blockiert;
- Client mit `accept_ra=0`;
- Switch/AP blockiert Multicast/ICMPv6.

### ULA, aber keine GUA

- der Upstream hat kein IPv6/PD;
- `wan6` nicht konfiguriert / Präfix nicht empfangen;
- der Provider liefert nur ein `/64`, das sich nicht für das LAN aufteilen lässt;
- Relay-/ND-Proxy-Szenarien sind anders; erzwingen Sie sie nicht.

### Adresse, aber kein Internet

- keine IPv6-Standardroute;
- Firewall-Weiterleitung/ICMPv6;
- DNS nur über IPv4;
- Upstream-Route/Präfix ungültig.

### IPv4 wird nach dem Aktivieren von IPv6 langsamer oder fällt aus

- DNS-Präferenz/Dual-Stack-Fallback;
- Privacy-Adressen des Clients/RA-Parameter;
- sorgen Sie dafür, dass IPv4 funktioniert; fügen Sie IPv6 Schritt für Schritt hinzu.
