## In einer Zeile

- **25.12+**: `apk`, Pakete sind `.apk`;
- **24.10 und älter**: `opkg`, Pakete sind `.ipk`;
- Sie sind nicht durch Umbenennen verwandt; **benennen Sie `.ipk` nicht in `.apk` um**;
- Installieren Sie nach dem Upgrade auf 25.12 Plugins aus den `apk`-Feeds neu; die Konfiguration kann gesichert/wiederhergestellt werden.

## Prüfen, auf welcher Seite Sie sind

```sh
cat /etc/openwrt_release
command -v apk
command -v opkg
```

In diesem Labor: 25.12.6, `apk` ist vorhanden, `opkg` nicht.

## Vergleich

| Punkt | 25.12 `apk` | 24.10 `opkg` |
|---|---|---|
| Format | `.apk` | `.ipk` |
| Feed-Datei | `/etc/apk/repositories.d/distfeeds.list` | `/etc/opkg/distfeeds.conf` |
| Index aktualisieren | `apk update` | `opkg update` |
| Installieren | `apk add <pkg>` | `opkg install <pkg>` |
| Entfernen | `apk del <pkg>` | `opkg remove <pkg>` |
| Suchen | `apk search <term>` | `opkg list \| grep <term>` |
| Installiert | `apk list --installed` | `opkg list-installed` |
| Paketinfo | `apk info -a <pkg>` | `opkg info <pkg>` |
| Cache leeren | `apk cache clean` | `opkg clean` |

## Feeds und Architektur

25.12:

```text
https://downloads.openwrt.org/releases/25.12.6/targets/x86/64/packages/packages.adb
https://downloads.openwrt.org/releases/25.12.6/packages/x86_64/base/packages.adb
https://downloads.openwrt.org/releases/25.12.6/targets/x86/64/kmods/<kernel-hash>/packages.adb
```

24.10:

```text
src/gz openwrt_core https://downloads.openwrt.org/releases/24.10.8/targets/x86/64/packages
src/gz openwrt_base https://downloads.openwrt.org/releases/24.10.8/packages/x86_64/base
```

- `release`, `target`, `arch` und kmod-Hash müssen übereinstimmen;
- Das Mischen von offiziellen/ImmortalWrt-/iStoreOS-Feeds kann ABI/Signaturen/Namen brechen;
- Ein China-Mirror ändert nur Host/Pfadpräfix; ändern Sie nicht Target/Arch.

## Beim Upgrade auf 25.12

1. Sichern Sie `/etc/config` und die Paketliste (siehe 018);
2. Notieren Sie `opkg list-installed` von 24.10;
3. Führen Sie das Upgrade durch bzw. flashen Sie 25.12 neu (siehe 019);
4. Installieren Sie Plugins aus den `apk`-Feeds neu;
5. Stellen Sie die Konfiguration wieder her und prüfen Sie LuCI/Dienste/DNS;
6. Konvertieren Sie `.ipk` nicht in `.apk` und kopieren Sie keine alten Paketverzeichnisse.

Das 25.12-sysupgrade in diesem Labor behielt die Konfiguration, verlor aber Pakete (239→182); SQM/OpenClash mussten neu installiert werden.

## Häufige Fehler

### `apk: not found`

- Die Firmware ist 24.10 oder älter; verwenden Sie `opkg`;
- „Einen apk-Paketmanager installieren“ ist nicht die Lösung; prüfen Sie zuerst das Release.

### `opkg: not found`

- Die Firmware ist 25.12+; verwenden Sie `apk`;
- Alte Anleitungen/Skripte mit `opkg` sind nicht direkt anwendbar.

### `.ipk` lässt sich nicht installieren

- 25.12 verwendet `.apk`;
- Umbenennen ändert das Format nicht;
- Suchen Sie die `.apk` für Release/Target/Arch oder bauen Sie neu.

### 404-/Signatur-/Abhängigkeitsfehler

- Release/Target/Arch/kmod-Hash passen nicht;
- gemischte Feeds;
- Systemzeit/Zertifikate;
- umgehen Sie das nicht routinemäßig mit `--allow-untrusted`.

### Nach dem Upgrade kein LuCI-Menü

- Das Hauptprogramm wurde ohne `luci-app-*` installiert;
- das alte Plugin wurde nicht neu installiert;
- Browser-Cache/erneut anmelden;
- siehe 017.
