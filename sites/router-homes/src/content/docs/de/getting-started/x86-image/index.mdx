## Die Auswahl in einer Zeile

- **PVE-Standard SeaBIOS**: bevorzugen Sie `generic-ext4-combined.img.gz` (hier getestet);
- **UEFI/OVMF**: wählen Sie ein combined-Image mit `-efi`;
- **Zurücksetzen auf Werkseinstellungen/schreibgeschütztes Root + Overlay**: wählen Sie squashfs combined;
- **vorhandener Bootloader bzw. vorhandene Partitionen, nur das Rootfs ersetzen**: verwenden Sie ein rootfs-Image;
- **Container/chroot**: `rootfs.tar.gz`, kein Festplatten-Image.

## Den Dateinamen lesen

Wichtigste Dateien für 25.12.6 x86/64:

```text
openwrt-25.12.6-x86-64-generic-ext4-combined.img.gz
openwrt-25.12.6-x86-64-generic-ext4-combined-efi.img.gz
openwrt-25.12.6-x86-64-generic-squashfs-combined.img.gz
openwrt-25.12.6-x86-64-generic-squashfs-combined-efi.img.gz
openwrt-25.12.6-x86-64-generic-ext4-rootfs.img.gz
openwrt-25.12.6-x86-64-generic-squashfs-rootfs.img.gz
openwrt-25.12.6-x86-64-generic-kernel.bin
openwrt-25.12.6-x86-64-generic-targz-rootfs.tar.gz
openwrt-25.12.6-x86-64-rootfs.tar.gz
```

Drei Begriffe sind entscheidend:

| Begriff | Bedeutung | Bei falscher Wahl |
|---|---|---|
| `combined` | Image der ganzen Festplatte mit Partitionstabelle/Boot | als rootfs verwendet, kann es Partitionen überschreiben |
| `rootfs` | nur das Dateisystem | kein Bootloader; bootet nicht direkt |
| `ext4` / `squashfs` | beschreibbares Root / schreibgeschütztes Root + Overlay | beeinflusst Wiederherstellung und Schreibverhalten |
| `-efi` | UEFI-Start | Legacy-BIOS bootet es möglicherweise nicht |
| `tar.gz` | rootfs-Archiv | kein bootfähiges Festplatten-Image |

## ext4 gegenüber squashfs

- **ext4 combined**: beschreibbares Root; üblich bei VMs/Soft-Routern; verhält sich wie eine normale Linux-Installation.
- **squashfs combined**: schreibgeschütztes Root, Konfiguration im Overlay; besser für das Zurücksetzen auf Werkseinstellungen und gegen Fehlbedienung; anderer Speicherbedarf und Wartungsaufwand.
- Beide können in PVE booten; dieser Laborlauf hat nur ext4 getestet. Verzichten Sie nicht auf Sicherungen, weil „squashfs sicherer ist“.

## BIOS gegenüber UEFI

- PVE-Standard `SeaBIOS`: verwenden Sie ein combined-Image ohne `-efi`;
- PVE `OVMF (UEFI)`: verwenden Sie combined mit `-efi` und richten Sie einen EFI-Datenträger ein;
- Physisch: prüfen Sie `UEFI/Legacy` in der Firmware und passen Sie das Image an;
- Falsche Wahl: kein Boot-Eintrag, GRUB startet nicht, Fallback auf PXE/BIOS.

Dieser Laborlauf: PVE-VM 200, SeaBIOS + `generic-ext4-combined`; Start erfolgreich.

## In PVE importieren

<Step where="pve" title="Datenträger importieren und Boot-Reihenfolge setzen" expected="Die VM bootet vom importierten Datenträger, nicht von ISO/PXE.">

```sh
qm create 200 --name openwrt --memory 512 --cores 2 --cpu host \
  --scsihw virtio-scsi-pci --ostype l26 --vga std --serial0 socket \
  --net0 virtio,bridge=vmbr0

qm importdisk 200 openwrt-25.12.6-x86-64-generic-ext4-combined.img local-lvm
qm set 200 --scsi0 local-lvm:vm-200-disk-0
qm set 200 --boot order=scsi0
qm start 200
```

Verwendet PVE UEFI/OVMF, nutzen Sie das `-efi`-Image und einen EFI-Datenträger; erzwingen Sie kein BIOS-Image unter UEFI.

</Step>

<Step where="pve" title="Start verifizieren" expected="Die Konsole zeigt OpenWrt sowie die richtige Version bzw. das richtige Target.">

```sh
qm terminal 200
# or inside the VM
ubus call system board
cat /etc/openwrt_release
```

Dieser Laborlauf startete 25.12.6 x86/64; Standard-LAN `192.168.1.1`.

</Step>

## Schreiben auf einen physischen Datenträger

```sh
# verify the target first; do not copy the wrong device name
lsblk
sudo dd if=openwrt-...-combined.img of=/dev/sdX bs=4M status=progress conv=fsync
sync
```

- `dd` überschreibt das gesamte Ziel; trennen Sie unbeteiligte Datenträger bzw. verifizieren Sie das Gerät;
- Wählen Sie für UEFI `-efi`;
- Booten Sie von diesem Datenträger; lassen Sie die ISO nicht die Boot-Priorität behalten;
- Namen physischer Netzwerkkarten stimmen möglicherweise nicht mit `eth0/eth1` in PVE überein; identifizieren Sie sie anhand von MAC/PCI.

## Häufige Fehler

### PVE-Import bootet nicht

- die Boot-Reihenfolge ist nicht `scsi0`;
- Sie haben rootfs statt combined gewählt;
- BIOS-/UEFI-Image passen nicht zusammen;
- Datenträger-Bus bzw. Controller passen nicht;
- die serielle Konsole ist nicht konfiguriert, daher gibt es kein Boot-Log.

### Physischer UEFI-Start schlägt fehl

- Image ohne `-efi`;
- das BIOS steht noch auf Legacy/CSM;
- unvollständig geschriebener USB-Stick;
- Einschränkungen durch Secure Boot/Signaturen.

### Das ursprüngliche System ist nach dem Schreiben verschwunden

`dd` hat den falschen Datenträger beschrieben. Sichern Sie Ihre Daten, prüfen Sie Größe/Modell mit `lsblk` und schreiben Sie erst dann; testen Sie nicht auf einem Produktivrechner.

### rootfs-Image bootet nicht direkt

rootfs enthält keinen Bootloader und keine Partitionstabelle; verwenden Sie einen vorhandenen Bootloader oder den passenden Container-/Virtualisierungsweg.
