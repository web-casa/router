## 升級不只是「換個韌體檔」

請分開看四件事：

1. **韌體**是否刷寫成功並能開機；
2. **設定**是否保留／還原；
3. **套件／外掛**是否仍在，或必須重新安裝；
4. **管理功能／DNS／WAN** 是否恢復。

保留設定不代表保留套件。保留某個應用程式的設定，也不代表保留它的二進位檔。

## 升級前

<Step where="router-shell" title="記錄 release、target、套件清單並備份" expected="你可以還原，並且知道哪些東西不見了。">

```sh
cat /etc/openwrt_release
cat /etc/apk/arch 2>/dev/null
apk list --installed > /tmp/packages-$(date +%F).txt
wc -l /tmp/packages-$(date +%F).txt
sysupgrade -b /tmp/pre-upgrade-$(date +%F).tar.gz
sha256sum /tmp/pre-upgrade-$(date +%F).tar.gz
```

將設定存檔複製到裝置外；若是 VM，也請建立 PVE 快照／備份。不要只留在 `/tmp`。

</Step>

<Step where="router-shell" title="驗證映像檔與檢查碼" expected="映像檔符合 release／target／arch，且檢查碼有效。">

```sh
wget -O /tmp/openwrt.img.gz <official-image-url>
sha256sum /tmp/openwrt.img.gz
# compare with the matching line in official sha256sums
gzip -dkf /tmp/openwrt.img.gz
ls -lh /tmp/openwrt.img
```

本實驗使用 25.12.6 x86/64 combined ext4 映像檔；`.img.gz` 的 SHA-256 相符，之後解壓縮再交給 `sysupgrade`。

</Step>

<Step where="router-shell" title="保留主控台與還原途徑" expected="升級中斷／失敗時可以復原。">

- 實體裝置：序列埠／HDMI、failsafe 按鍵、舊版韌體；
- PVE：升級前建立快照，並確認 `qm rollback` 可用；
- 記錄 LAN IP、DHCP、WAN、DNS、管理連接埠；
- 升級期間不要斷電或拔除磁碟。

</Step>

## 升級命令

預設（保留設定）：

```sh
sysupgrade -v /tmp/openwrt.img
```

選項：

- `-n`：不保留設定（全新安裝）；
- `-f <backup.tar.gz>`：升級時還原設定；
- `-c`/`-o`：保留更多變更過的檔案；邊界較為複雜；
- 除非完全了解後果，否則不要用 `-F` 忽略相容性檢查。

升級會關閉 SSH／網頁連線；請等待重新啟動，不要因為連線失敗就切斷電源。

## 升級後驗證

<Step where="client" title="管理入口" expected="至少各檢查一次 LAN IP、HTTP 與 SSH。">

```sh
ping -c 2 192.168.1.2
curl -sSI --max-time 5 http://192.168.1.2/ | head -3
ssh root@192.168.1.2 'cat /etc/openwrt_release'
```

本實驗保留了 LAN `192.168.1.2/24`；HTTP 200，SSH 正常。

</Step>

<Step where="router-shell" title="設定與 DNS／WAN" expected="設定被保留，且 DNS／WAN 確實可用。">

```sh
uci show network.lan.ipaddr
uci show dhcp.lan
ip route
nslookup openwrt.org 127.0.0.1
logread | grep -Ei 'dnsmasq|netifd|dhcp' | tail -30
```

本實驗：升級後 DNS 與 HTTP 正常；WAN 設定被保留。仍須重新驗證用戶端的 DHCP 租約與真實的網際網路連線，而不是只看路由器本身。

</Step>

<Step where="router-shell" title="套件與外掛" expected="你知道遺失了什麼，並依清單重新安裝。">

```sh
apk list --installed | wc -l
for p in sqm-scripts luci-app-sqm luci-app-openclash; do
  apk info -e "$p" && echo "$p installed" || echo "$p MISSING"
done
```

本實驗：升級前 239 個套件，升級後 182 個；`sqm-scripts`、`luci-app-sqm`、`luci-app-openclash` 全部不見。設定可能還在，但二進位檔必須重新安裝。

逐一重新安裝：

```sh
apk update
apk add sqm-scripts luci-app-sqm
# verify menu/service before the next package
```

不要一次還原所有外掛；請先恢復管理功能／DNS／基本網路。

</Step>

## 重建順序

1. 基本網路：network/dhcp/firewall；
2. DNS：dnsmasq，需要時再裝 AGH；
3. 管理：luci/uhttpd；
4. 代理／流量整形：OpenClash、SQM；
5. 最後：規則／訂閱／效能調校。

每安裝一個套件都要檢查：

- 是否已安裝；
- LuCI 選單／控制器是否存在；
- 服務是否啟動；
- DNS／預設路由是否被更動；
- 停用它後是否恢復基本網路。

## 還原

- 實體裝置：保留舊版韌體／復原模式；
- PVE：升級前建立快照／`vzdump`，失敗時還原整台 VM；
- 設定：用 `sysupgrade -r` 還原存檔；
- 不要用「再刷一次」來取代診斷失敗原因。

本實驗使用快照 `pre-019`；記錄結果後已還原到升級前的狀態。本頁記錄的是實際的升級執行結果。
