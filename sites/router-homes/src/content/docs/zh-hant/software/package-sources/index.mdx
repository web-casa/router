首先要知道：**apk 與 opkg 的差異**取決於韌體版本，而不是「哪個鏡像站比較快」。25.12 使用 `apk`；24.10 使用 `opkg`。套件格式、套件來源路徑與驗證方式都不同，兩者不能互換。

## 預期結果

- 知道韌體使用 `apk` 還是 `opkg`，以及它的套件來源檔位於何處。
- 對齊版本、target、架構與 kmods 核心雜湊值。
- 知道中國鏡像站取代的是 URL 的哪一部分，以及哪些路徑必須保持一致。
- 了解為什麼「更換鏡像站後套件裝不起來」，以及如何回復。
- 了解為什麼 `apk upgrade`/`opkg upgrade` 不是韌體升級。

## 辨識套件管理員與套件來源

<Step where="router-shell" title="讀取版本、target 與架構" expected="你能寫出完整的版本/target/架構組合。">

```sh
ubus call system board
cat /etc/openwrt_release
uname -m
cat /etc/apk/arch 2>/dev/null
opkg print-architecture 2>/dev/null
```

關鍵欄位：`release.version`、`release.target`、`DISTRIB_ARCH`、`release.revision`。它們必須與鏡像站路徑相符。

</Step>

<Step where="router-shell" title="檢查目前的套件來源檔" expected="你知道每個來源指向哪裡，以及它是 apk 還是 opkg。">

OpenWrt 25.12（apk）：

```sh
cat /etc/apk/repositories.d/distfeeds.list
```

OpenWrt 24.10（opkg）：

```sh
cat /etc/opkg/distfeeds.conf
cat /etc/opkg/customfeeds.conf
```

編輯之前先備份：

```sh
cp /etc/apk/repositories.d/distfeeds.list /etc/apk/repositories.d/distfeeds.list.bak.$(date +%F) 2>/dev/null || true
cp /etc/opkg/distfeeds.conf /etc/opkg/distfeeds.conf.bak.$(date +%F) 2>/dev/null || true
```

</Step>

## 25.12 的 apk 結構

OpenWrt 25.12 使用 `apk`；索引為 `.adb`，套件為 `.apk`。典型的套件來源：

- `targets/<target>/packages/packages.adb`：target 專屬套件；
- `packages/<arch>/base/packages.adb`：base；
- `packages/<arch>/luci/packages.adb`：LuCI；
- `packages/<arch>/packages/packages.adb`：一般套件；
- `packages/<arch>/routing|telephony|video/packages.adb`：分類套件來源；
- `targets/<target>/kmods/<kernel-hash>/packages.adb`：核心模組；雜湊值必須與正在執行的核心相符。

指令：

```sh
apk update
apk search <name>
apk add <name>
apk info -e <name>
```

請勿使用 `opkg`，也不要把 24.10 的 `.ipk` 改名為 `.apk`。

## 24.10 的 opkg 結構

OpenWrt 24.10 使用 `opkg`；索引為 `Packages.gz`，套件為 `.ipk`：

```sh
opkg update
opkg list | grep <name>
opkg install <name>
opkg list-installed | grep <name>
```

請勿使用 `apk`，也不要把 25.12 的 `.apk` 交給 opkg。

## 改寫為中國鏡像站

以 TUNA 鏡像站為例，根路徑為：

```text
https://mirrors.tuna.tsinghua.edu.cn/openwrt/
```

只把 `https://downloads.openwrt.org` 換成該根路徑，並**保留完整的路徑**：

```text
https://downloads.openwrt.org/releases/25.12.6/targets/x86/64/packages/packages.adb
→ https://mirrors.tuna.tsinghua.edu.cn/openwrt/releases/25.12.6/targets/x86/64/packages/packages.adb
```

不要只寫到 `.../openwrt/`，也不要省略 `releases/25.12.6/targets/x86/64/...`；路徑不完整會回傳 404。

<Step where="router-shell" title="編輯前先驗證鏡像站路徑" expected="curl 回傳 200，且路徑與目前的版本/target 相符。">

```sh
curl -I https://mirrors.tuna.tsinghua.edu.cn/openwrt/releases/25.12.6/targets/x86/64/packages/packages.adb
```

請把 URL 換成你的版本/target；若是 kmods，也要驗證核心雜湊值。若鏡像站沒有該路徑，不要強行使用。

</Step>

<Step where="router-shell" title="只更新索引，不要升級系統" expected="apk/opkg update 成功，且不會大量升級套件。">

```sh
apk update
# or
opkg update
```

使用 `apk search`/`opkg list` 確認套件來源可讀取，再只安裝你需要的套件。**不要**把 `apk upgrade`/`opkg upgrade` 當成韌體升級；韌體請使用 sysupgrade/ASU/owut。

</Step>

## 常見失敗

### 404

- 版本錯誤（25.12.6 與 24.10.8）；
- target 錯誤（是 `x86/64`，不是 `x86_64` 目錄）；
- 架構錯誤（`x86_64`、`aarch64`）；
- 鏡像站尚未同步該路徑；
- 混淆了 `packages` 與 `targets` 目錄。

### 簽章/驗證失敗

- 索引損毀或屬於不同版本；
- 系統時間/憑證錯誤；
- 混入了其他套件來源；
- 不要依賴 `--allow-untrusted`；請修正套件來源/驗證。

### 相依性/ABI 不符

- kmods 核心雜湊值不符；
- 套件是為其他 target/架構建置的；
- 混用官方與 ImmortalWrt/iStoreOS 套件來源；
- 你需要相同的來源、版本與架構，或自行重新建置。

### 找不到指令

- 25.12 沒有 `opkg`；24.10 沒有 `apk`；
- 不要為了執行某個指令而安裝套件管理員；請先辨識韌體/來源。

### 套件已安裝，但 LuCI 沒有顯示

- 只安裝了核心套件，缺少 `luci-app-*` 套件；
- 缺少語言套件；
- 瀏覽器快取/重新整理；
- 套件版本與 LuCI 不符。

## 回復

```sh
# apk
cp /etc/apk/repositories.d/distfeeds.list.bak.YYYY-MM-DD /etc/apk/repositories.d/distfeeds.list
apk update

# opkg
cp /etc/opkg/distfeeds.conf.bak.YYYY-MM-DD /etc/opkg/distfeeds.conf
opkg update
```

若更換鏡像站後更新失效，請先還原官方來源，驗證 DNS/時間/憑證，再重試鏡像站。不要在許多鏡像站之間跳來跳去。
