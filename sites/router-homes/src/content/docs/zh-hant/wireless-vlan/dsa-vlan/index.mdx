## DSA 與 swconfig 的差異

- 較舊的裝置常使用 `swconfig`：`switch0`、連接埠 0/1/2；
- DSA 會把每個連接埠呈現為 `lan1`、`lan2`、`wan` 等；
- 現代 OpenWrt 使用 **bridge VLAN filtering**（橋接 VLAN 篩選），而不是 `swconfig` 的 `vid/ports` 語法；
- 連接埠名稱因裝置而異：`ip -d link show`、`ls /sys/class/net`。

## bridge-vlan 範例

假設 DSA 連接埠為 `lan1`、`lan2`、`lan3`；讓 `lan1` 成為 trunk（VLAN 1 + 20 tagged），`lan2/lan3` 為 VLAN 1 的 access：

```uci
config device
    option name 'br-lan'
    option type 'bridge'
    list ports 'lan1'
    list ports 'lan2'
    list ports 'lan3'

config bridge-vlan
    option device 'br-lan'
    option vlan '1'
    list ports 'lan1:u*'
    list ports 'lan2:u*'
    list ports 'lan3:u*'

config bridge-vlan
    option device 'br-lan'
    option vlan '20'
    list ports 'lan1:t'
```

重點：

- `u*`：untagged，且為該連接埠在此 VLAN 的 PVID；
- `t`：tagged，透過 trunk 傳送；
- access 連接埠通常只有一個 untagged PVID；
- 交換器之間的 trunk，兩端都必須是 tagged，並允許相同的 VLAN；
- 不要讓舊的 `swconfig` 設定與此並存。

> 請依你的裝置替換連接埠名稱/CPU 連接埠；若不確定，請先在備用連接埠/裝置上測試。

## 套用並驗證

```sh
uci commit network
/etc/init.d/network reload
bridge vlan show
ip -d link show br-lan
```

驗證：

- 管理介面仍能連到 LuCI/SSH；
- access 用戶端能從正確的 VLAN 取得 DHCP；
- trunk 對端能看到 tagged 的 VLAN；
- `bridge vlan show` 與 PVID/tagged 的設計一致。

## 失去連線後的回復

1. 使用主控台/序列埠；不要只依賴網路；
2. 還原 `/etc/config/network.bak.*`；
3. 或暫時把管理連接埠改回 untagged VLAN 1；
4. 重新啟動網路並確認可以管理；
5. 一次只新增一個連接埠的 VLAN。

## 常見故障

### 立刻失去連線

- 管理連接埠被改成 tagged 或 PVID 錯誤；
- trunk 對端不允許該 VLAN；
- CPU/上行連接埠被一次全部改動；
- 透過主控台回復；不要盲目恢復原廠設定。

### 無法連到 VLAN 20

- 兩端的 tagged/untagged 不一致；
- 未設定 PVID；
- 該 VLAN 沒有介面/DHCP/防火牆；
- 交換器上未建立/未允許該 VLAN。

### 有位址但無法上網

- 訪客/服務 VLAN 缺少 DHCP/DNS；
- 防火牆區域/轉送不一致；
- 缺少 NAT/回程路由；
- VLAN 連通性不等於路由/NAT。
