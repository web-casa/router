## アップグレードは「ファームウェアファイルを入れ替えるだけ」ではない

次の4つを分けて考えます。

1. **ファームウェア**が書き込まれ、起動したか
2. **設定**が維持/復元されたか
3. **パッケージ/プラグイン**が残っているか、再インストールが必要か
4. **管理アクセス/DNS/WAN**が復旧したか

設定を維持してもパッケージは維持されません。アプリの設定を維持しても、そのバイナリは維持されません。

## アップグレードの前に

<Step where="router-shell" title="リリース、ターゲット、パッケージ一覧を記録してバックアップする" expected="ロールバックでき、何が消えたかが分かります。">

```sh
cat /etc/openwrt_release
cat /etc/apk/arch 2>/dev/null
apk list --installed > /tmp/packages-$(date +%F).txt
wc -l /tmp/packages-$(date +%F).txt
sysupgrade -b /tmp/pre-upgrade-$(date +%F).tar.gz
sha256sum /tmp/pre-upgrade-$(date +%F).tar.gz
```

設定アーカイブはデバイス外にコピーしてください。VMの場合はPVEのスナップショット/バックアップも取得します。`/tmp` にだけ置かないでください。

</Step>

<Step where="router-shell" title="イメージとチェックサムを検証する" expected="イメージがリリース/ターゲット/アーキテクチャと一致し、チェックサムが有効です。">

```sh
wget -O /tmp/openwrt.img.gz <official-image-url>
sha256sum /tmp/openwrt.img.gz
# 公式sha256sumsの該当行と比較する
gzip -dkf /tmp/openwrt.img.gz
ls -lh /tmp/openwrt.img
```

このテストでは25.12.6 x86/64のcombined ext4イメージを使いました。`.img.gz` のSHA-256が一致したことを確認し、展開して `sysupgrade` に渡しています。

</Step>

<Step where="router-shell" title="コンソールとロールバック手段を確保する" expected="アップグレードの中断や失敗から復旧できます。">

- 物理デバイス: シリアル/HDMI、フェイルセーフ用のキー、旧ファームウェア
- PVE: アップグレード前にスナップショットを取り、`qm rollback` を確認する
- LAN IP、DHCP、WAN、DNS、管理ポートを記録する
- アップグレード中に電源を切ったり、ディスクを取り外したりしない

</Step>

## アップグレードコマンド

デフォルト（設定を維持）:

```sh
sysupgrade -v /tmp/openwrt.img
```

オプション:

- `-n`: 設定を維持しない（クリーンインストール）
- `-f <backup.tar.gz>`: アップグレード中に設定を復元する
- `-c`/`-o`: 変更されたファイルをより多く保持する。境界が複雑になる
- 内容を十分に理解している場合を除き、互換性チェックを無視する `-F` は使わない

アップグレードによりSSH/Webセッションは切断されます。接続が切れたからといって電源を切らず、再起動を待ってください。

## アップグレード後の確認

<Step where="client" title="管理アクセス" expected="LAN IP、HTTP、SSHを少なくとも一度ずつ確認します。">

```sh
ping -c 2 192.168.1.2
curl -sSI --max-time 5 http://192.168.1.2/ | head -3
ssh root@192.168.1.2 'cat /etc/openwrt_release'
```

このテストではLAN `192.168.1.2/24` が維持され、HTTP 200とSSHが動作しました。

</Step>

<Step where="router-shell" title="設定とDNS/WAN" expected="設定が維持され、DNS/WANが実際に動作しています。">

```sh
uci show network.lan.ipaddr
uci show dhcp.lan
ip route
nslookup openwrt.org 127.0.0.1
logread | grep -Ei 'dnsmasq|netifd|dhcp' | tail -30
```

このテスト環境: アップグレード後もDNSとHTTPが動作し、WAN設定は維持されました。ただし、ルーター自身だけでなく、クライアントのDHCPリースと実際のインターネット接続も再確認してください。

</Step>

<Step where="router-shell" title="パッケージとプラグイン" expected="何が失われたかが分かり、一覧から再インストールできます。">

```sh
apk list --installed | wc -l
for p in sqm-scripts luci-app-sqm luci-app-openclash; do
  apk info -e "$p" && echo "$p installed" || echo "$p MISSING"
done
```

このテスト環境: アップグレード前は239個、後は182個。`sqm-scripts`、`luci-app-sqm`、`luci-app-openclash` はすべて消えていました。設定は残っていても、バイナリは再インストールが必要です。

1つずつ再インストールします。

```sh
apk update
apk add sqm-scripts luci-app-sqm
# 次のパッケージに進む前に、メニュー/サービスを確認する
```

すべてのプラグインを一度に復元しないでください。まず管理アクセス、DNS、基本的なネットワークを復旧させます。

</Step>

## 再構築の順序

1. 基本ネットワーク: network/dhcp/firewall
2. DNS: dnsmasq、必要ならその後にAGH
3. 管理: luci/uhttpd
4. プロキシ/シェーピング: OpenClash、SQM
5. 最後に: ルール/サブスクリプション/性能チューニング

各パッケージで確認すること:

- インストールされているか
- LuCIのメニュー/コントローラーがあるか
- サービスが起動するか
- DNS/デフォルトルートが変更されていないか
- 無効化すると基本ネットワークが復旧するか

## ロールバック

- 物理デバイス: 旧ファームウェア/リカバリーモードを保管しておく
- PVE: アップグレード前のスナップショット/`vzdump` を使い、失敗したらVM全体をロールバックする
- 設定: アーカイブを `sysupgrade -r` で復元する
- 失敗の原因を調べる代わりに「もう一度書き換える」ことはしない

このテストではスナップショット `pre-019` を使い、結果を記録した後にアップグレード前の状態へロールバックしました。このページは実際のアップグレード実行を記録したものです。
