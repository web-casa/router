## DSA と swconfig の違い

- 古いデバイスでは `swconfig` が使われることが多く、`switch0` やポート 0/1/2 で表します。
- DSA では各ポートが `lan1`、`lan2`、`wan` などとして見えます。
- 現在の OpenWrt では、`swconfig` の `vid/ports` 構文ではなく **bridge VLAN filtering** を使います。
- ポート名はデバイスによって異なります。`ip -d link show` や `ls /sys/class/net` で確認してください。

## bridge-vlan の例

DSA ポートが `lan1`、`lan2`、`lan3` だとします。`lan1` をトランク (VLAN 1 と 20 を tagged) にし、`lan2` と `lan3` を VLAN 1 のアクセスポートにします。

```uci
config device
    option name 'br-lan'
    option type 'bridge'
    list ports 'lan1'
    list ports 'lan2'
    list ports 'lan3'

config bridge-vlan
    option device 'br-lan'
    option vlan '1'
    list ports 'lan1:u*'
    list ports 'lan2:u*'
    list ports 'lan3:u*'

config bridge-vlan
    option device 'br-lan'
    option vlan '20'
    list ports 'lan1:t'
```

ポイント:

- `u*`: untagged で、その VLAN におけるこのポートの PVID です。
- `t`: tagged で、トランク経由で運ばれます。
- アクセスポートの untagged PVID は、通常 1 つだけです。
- スイッチ間のトランクは、両端とも tagged にし、同じ VLAN を許可する必要があります。
- 古い `swconfig` の設定を残したまま併用しないでください。

> ポート名や CPU ポートはお使いのデバイスに合わせて置き換えてください。不安な場合は、予備のポートやデバイスでテストしてください。

## 適用と確認

```sh
uci commit network
/etc/init.d/network reload
bridge vlan show
ip -d link show br-lan
```

確認項目:

- 管理用の LuCI/SSH に引き続き接続できる。
- アクセスポートのクライアントが、正しい VLAN の DHCP からアドレスを取得できる。
- トランクの接続先で tagged の VLAN が見える。
- `bridge vlan show` の内容が、設計した PVID/tagged と一致している。

## 接続できなくなった場合の復旧

1. コンソール/シリアルを使います。ネットワークだけに頼らないでください。
2. `/etc/config/network.bak.*` を復元します。
3. または、管理用ポートを一時的に untagged の VLAN 1 に戻します。
4. ネットワークを再起動し、管理に接続できることを確認します。
5. VLAN はポートを 1 つずつ追加します。

## よくある失敗

### 変更直後に接続できなくなる

- 管理用ポートを tagged に変えた、または PVID が間違っている。
- トランクの接続先がその VLAN を許可していない。
- CPU/アップリンクのポートをまとめて変更した。
- コンソールから復旧します。むやみに初期化しないでください。

### VLAN 20 に到達できない

- 両端で tagged/untagged が一致していない。
- PVID が設定されていない。
- その VLAN 用のインターフェース/DHCP/ファイアウォールがない。
- スイッチ側で VLAN が作成または許可されていない。

### アドレスは取得できるがインターネットに出られない

- ゲスト/サービス用 VLAN に DHCP/DNS がない。
- ファイアウォールのゾーンやフォワーディングが一致していない。
- NAT や戻りのルートがない。
- VLAN で通信できることは、ルーティングや NAT ができることとは別です。
