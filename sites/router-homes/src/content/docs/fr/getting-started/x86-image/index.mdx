## Le choix en une ligne

- **SeaBIOS, par défaut sous PVE** : préférez `generic-ext4-combined.img.gz` (testé ici) ;
- **UEFI/OVMF** : choisissez une image combined avec `-efi` ;
- **réinitialisation d'usine, racine en lecture seule + overlay** : choisissez squashfs combined ;
- **bootloader et partitions existants, remplacement du rootfs seul** : utilisez une image rootfs ;
- **conteneur/chroot** : `rootfs.tar.gz`, pas une image de disque.

## Lire le nom de fichier

Principaux fichiers x86/64 de la version 25.12.6 :

```text
openwrt-25.12.6-x86-64-generic-ext4-combined.img.gz
openwrt-25.12.6-x86-64-generic-ext4-combined-efi.img.gz
openwrt-25.12.6-x86-64-generic-squashfs-combined.img.gz
openwrt-25.12.6-x86-64-generic-squashfs-combined-efi.img.gz
openwrt-25.12.6-x86-64-generic-ext4-rootfs.img.gz
openwrt-25.12.6-x86-64-generic-squashfs-rootfs.img.gz
openwrt-25.12.6-x86-64-generic-kernel.bin
openwrt-25.12.6-x86-64-generic-targz-rootfs.tar.gz
openwrt-25.12.6-x86-64-rootfs.tar.gz
```

Trois mots comptent :

| Mot | Signification | En cas d'erreur |
|---|---|---|
| `combined` | image de disque entier avec table de partitions et démarrage | l'utiliser comme rootfs peut écraser des partitions |
| `rootfs` | système de fichiers seul | pas de bootloader ; ne peut pas démarrer directement |
| `ext4` / `squashfs` | racine inscriptible / racine en lecture seule + overlay | influe sur la récupération et le comportement en écriture |
| `-efi` | démarrage UEFI | le BIOS Legacy peut ne pas le démarrer |
| `tar.gz` | archive rootfs | n'est pas une image de disque amorçable |

## ext4 ou squashfs

- **ext4 combined** : racine inscriptible ; courante pour les VM et routeurs logiciels ; se comporte comme une installation Linux classique.
- **squashfs combined** : racine en lecture seule, configuration dans l'overlay ; meilleure réinitialisation d'usine et protection contre les erreurs ; espace et maintenance différents.
- Les deux peuvent démarrer sous PVE ; cet essai n'a testé que ext4. Ne sautez pas les sauvegardes sous prétexte que « squashfs est plus sûr ».

## BIOS ou UEFI

- `SeaBIOS` par défaut sous PVE : utilisez une image combined sans `-efi` ;
- `OVMF (UEFI)` sous PVE : utilisez une image combined `-efi` et préparez un disque EFI ;
- Machine physique : vérifiez `UEFI/Legacy` dans le micrologiciel et faites correspondre ;
- Mauvais choix : aucune entrée de démarrage, GRUB ne se lance pas, retour au PXE/BIOS.

Cet essai : VM PVE 200, SeaBIOS + `generic-ext4-combined` ; démarrage réussi.

## Télécharger et vérifier

<Step where="client" title="Télécharger l'image et sha256sums" expected="La source officielle ou TUNA et la somme de contrôle sont validées.">

```sh
curl -LO https://downloads.openwrt.org/releases/25.12.6/targets/x86/64/openwrt-25.12.6-x86-64-generic-ext4-combined.img.gz
curl -LO https://downloads.openwrt.org/releases/25.12.6/targets/x86/64/sha256sums
grep 'generic-ext4-combined.img.gz' sha256sums | sha256sum -c -
```

Cet essai : `.img.gz` de 13,0 Mo, `.img` de 120,5 Mo après décompression ; le SHA-256 correspondait.

</Step>

<Step where="client" title="Décompresser" expected="Un .img prêt à être importé ou écrit.">

```sh
gzip -dk openwrt-25.12.6-x86-64-generic-ext4-combined.img.gz
ls -lh openwrt-25.12.6-x86-64-generic-ext4-combined.img
```

`sysupgrade` et `qm importdisk` de PVE utilisent le `.img` ; n'écrivez pas directement le `.gz` sur le disque.

</Step>

## Importer dans PVE

<Step where="pve" title="Importer le disque et définir l'ordre de démarrage" expected="La VM démarre depuis le disque importé, et non depuis l'ISO ou le PXE.">

```sh
qm create 200 --name openwrt --memory 512 --cores 2 --cpu host \
  --scsihw virtio-scsi-pci --ostype l26 --vga std --serial0 socket \
  --net0 virtio,bridge=vmbr0

qm importdisk 200 openwrt-25.12.6-x86-64-generic-ext4-combined.img local-lvm
qm set 200 --scsi0 local-lvm:vm-200-disk-0
qm set 200 --boot order=scsi0
qm start 200
```

Si PVE utilise UEFI/OVMF, prenez l'image `-efi` et un disque EFI ; ne forcez pas une image BIOS sur de l'UEFI.

</Step>

<Step where="pve" title="Vérifier le démarrage" expected="La console affiche OpenWrt avec la bonne version et la bonne target.">

```sh
qm terminal 200
# or inside the VM
ubus call system board
cat /etc/openwrt_release
```

Cet essai a démarré la version 25.12.6 x86/64 ; LAN par défaut `192.168.1.1`.

</Step>

## Écriture sur un disque physique

```sh
# verify the target first; do not copy the wrong device name
lsblk
sudo dd if=openwrt-...-combined.img of=/dev/sdX bs=4M status=progress conv=fsync
sync
```

- `dd` écrase toute la cible ; déconnectez les disques sans rapport et vérifiez le périphérique ;
- Pour l'UEFI, choisissez `-efi` ;
- Démarrez depuis ce disque ; ne laissez pas l'ISO garder la priorité de démarrage ;
- Les noms des cartes réseau physiques peuvent différer de `eth0/eth1` sous PVE ; identifiez-les par MAC ou PCI.

## Échecs courants

### L'import PVE ne démarre pas

- l'ordre de démarrage n'est pas `scsi0` ;
- vous avez choisi rootfs au lieu de combined ;
- image BIOS/UEFI inadaptée ;
- bus ou contrôleur de disque inadapté ;
- console série non configurée, donc aucun journal de démarrage.

### Le démarrage UEFI physique échoue

- image sans `-efi` ;
- le BIOS est toujours en Legacy/CSM ;
- écriture USB incomplète ;
- restrictions de Secure Boot ou de signature.

### Le système d'origine a disparu après l'écriture

`dd` a écrit sur le mauvais disque. Sauvegardez, vérifiez la taille et le modèle avec `lsblk`, puis écrivez ; ne testez pas sur une machine de production.

### L'image rootfs ne démarre pas directement

Le rootfs n'a ni bootloader ni table de partitions ; utilisez un bootloader existant ou la voie de conteneur ou de virtualisation appropriée.
