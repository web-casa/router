## Ce que signifie vraiment le mode AP

Un AP n'est pas « un autre routeur » :

- branchez le **port LAN**, pas le WAN ;
- désactivez le DHCP sur l'AP ; le routeur principal continue d'attribuer les baux ;
- placez l'IP LAN de l'AP en dehors de la plage DHCP du routeur principal ;
- ne faites pas de NAT ni de double routage, sauf si vous voulez volontairement un second routeur.

Ce laboratoire vérifie **uniquement un AP filaire + DHCP amont** ; le SSID, le chiffrement et l'itinérance Wi-Fi n'ont pas de matériel et sont E1.

## Topologie

```text
Main router 192.168.1.1 (DHCP)
        │ LAN port
        │
   OpenWrt AP
   LAN br-lan 192.168.1.2/24
   DHCP: ignore
        │ LAN port
        │
   Client 192.168.1.136/24
   gateway 192.168.1.1
```

- Le client obtient son bail du routeur principal ; la passerelle est `.1`, pas l'AP `.2` ;
- l'AP `.2` sert uniquement à l'administration ;
- si la passerelle du client devient `.2`, il existe un second serveur DHCP ou une mauvaise configuration.

## Configuration

<Step where="router-shell" title="Sauvegarder et confirmer que le WAN n'est pas nécessaire" expected="Vous connaissez l'IP LAN, l'état du DHCP et si le WAN est utilisé.">

```sh
uci show network.lan
uci show dhcp.lan
uci show network.wan 2>/dev/null
cp /etc/config/network /etc/config/network.bak.$(date +%F)
cp /etc/config/dhcp /etc/config/dhcp.bak.$(date +%F)
```

Le mode AP n'a généralement pas besoin du WAN ; s'il subsiste, assurez-vous qu'il ne s'approprie pas la route par défaut ni le NAT.

</Step>

<Step where="luci" title="Changer l'IP LAN, désactiver le DHCP" expected="L'AP est en 192.168.1.2/24 et n'attribue plus de baux.">

**Réseau → Interfaces → LAN → Éditer** :

1. Adresse IPv4 : `192.168.1.2/24` (hors de la plage du routeur principal) ;
2. **Serveur DHCP → Réglages généraux → Ignorer l'interface** ;
3. Enregistrez et appliquez.

Ligne de commande :

```sh
uci set network.lan.ipaddr='192.168.1.2/24'
uci set dhcp.lan.ignore='1'
uci commit network
uci commit dhcp
/etc/init.d/network reload
/etc/init.d/dnsmasq restart
```

Rouvrez ensuite LuCI/SSH à l'adresse `192.168.1.2`.

</Step>

<Step where="client" title="Se connecter au port LAN du routeur principal" expected="Le client obtient son bail du routeur principal, avec la passerelle principale.">

Reliez le **port LAN** d'OpenWrt au **port LAN** du routeur principal ; n'utilisez pas le WAN.

Reconnectez/renouvelez sur le client :

```sh
ip addr show
ip route
cat /etc/resolv.conf
ping 192.168.1.1
ping 192.168.1.2
```

Le client de ce laboratoire a obtenu `192.168.1.136/24`, passerelle `192.168.1.1` ; l'AP `.2` était joignable.

</Step>

<Step where="client" title="Confirmer que l'AP ne sert pas le DHCP" expected="Le serveur DHCP est le routeur principal, pas l'AP.">

```sh
# Linux example
udhcpc -i eth0 -f -q -n -t 5
```

Vérifiez `server 192.168.1.1` ; s'il indique `192.168.1.2`, le DHCP de l'AP est toujours actif.

Ce laboratoire AP seul n'avait pas d'internet, donc l'échec de `ping 1.1.1.1` est attendu ; l'accès réel à internet dépend du routeur principal.

</Step>

## AP sans fil (E1)

Pas de matériel sans fil, donc non vérifié :

- SSID/mot de passe/WPA2/WPA3 ;
- canal 2,4/5 GHz, largeur, puissance d'émission ;
- itinérance/802.11r/éjection des signaux faibles ;
- isolation des clients sans fil ;
- plusieurs AP avec un même SSID.

Principes :

- reliez l'interface sans fil au pont `br-lan` ;
- désactivez le DHCP ;
- utilisez WPA2/WPA3, jamais un réseau ouvert ;
- décalez les canaux, réutilisez le même SSID/mot de passe sur tous les AP ;
- vérifiez d'abord le filaire, puis ajoutez le Wi-Fi, afin de ne pas modifier deux couches à la fois.

## Échecs courants

### Tout le réseau tombe après l'ajout de l'AP

- Le DHCP de l'AP est toujours actif et entre en conflit avec le routeur principal ;
- l'IP LAN de l'AP est en conflit avec le routeur principal ;
- le port WAN de l'AP a été branché au LAN principal ;
- une boucle entre le routeur principal et l'AP.

Débranchez l'AP, rétablissez le routeur principal, puis modifiez un élément à la fois.

### Les clients n'obtiennent pas d'adresse

- L'AP n'est pas relié au LAN principal ;
- le DHCP de l'AP est désactivé mais celui du routeur principal est désactivé/saturé ;
- VLAN/port isolé ;
- l'interface sans fil n'est pas reliée en pont à `br-lan`.

### Les clients ont une adresse mais une mauvaise passerelle

- un autre serveur DHCP distribue `.2` ;
- le client a conservé un ancien bail ;
- l'AP exécute encore un serveur DHCP ;
- vérifiez `cat /tmp/dhcp.leases` (l'AP ne devrait avoir aucun nouveau bail).

### Le Wi-Fi se connecte mais pas d'internet

- l'interface sans fil n'est pas dans le pont LAN ;
- le pare-feu sépare les zones sans fil et LAN ;
- le routeur principal en amont le bloque ;
- isolation des clients/réseau invité.
