## Résultat attendu

- Déterminer si le paquet est absent du dépôt ou s'il existe mais échoue à l'installation ;
- Identifier un échec d'architecture, d'ABI, de dépendance, d'interface LuCI ou de postinst ;
- Comprendre pourquoi le programme principal s'est installé mais LuCI n'a pas de menu ;
- Récupérer sans reflasher le micrologiciel.

## Couche 0 : relever l'environnement

<Step where="router-shell" title="Relever le micrologiciel, l'architecture, le gestionnaire de paquets et les dépôts" expected="Vous savez s'il faut utiliser apk ou opkg, ainsi que la version, la cible et l'architecture.">

```sh
ubus call system board
cat /etc/openwrt_release
cat /etc/apk/arch 2>/dev/null
command -v apk
command -v opkg
cat /etc/apk/repositories.d/distfeeds.list 2>/dev/null
```

25.12 utilise `apk` ; 24.10 utilise `opkg`. Ne renommez pas un `.ipk` en `.apk` et ne forcez pas une autre architecture.

</Step>

## Couche 1 : téléchargement et dépôts

<Step where="router-shell" title="Confirmer que le paquet existe dans le dépôt" expected="apk search/update le trouve, ou vous savez qu'il est absent.">

```sh
apk update
apk search <package>
apk info -e <package>
```

Si `apk update` échoue, vérifiez d'abord les erreurs 404, la signature, l'heure et les certificats. Si la recherche ne trouve rien, le dépôt est peut-être périmé, le nom est peut-être erroné, ou le paquet n'existe pas pour cette version/architecture.

</Step>

<Step where="router-shell" title="Vérifier le format et la somme de contrôle avant d'installer" expected="La source est fiable et le format/l'architecture correspondent.">

- 25.12 : `.apk` ; 24.10 : `.ipk` ;
- Préférez les dépôts aux « repacks » de disque cloud ou de forum ;
- Pour les fichiers locaux, vérifiez le SHA-256 ou la signature ;
- **N'utilisez pas `--allow-untrusted` par routine** ; il contourne les contrôles de confiance et ne prouve pas la compatibilité.

</Step>

## Couche 2 : architecture et ABI

<Step where="router-shell" title="Vérifier l'architecture du paquet, pas le nom du fichier" expected="L'architecture du paquet correspond à /etc/apk/arch ; les kmods correspondent aussi au noyau.">

```sh
cat /etc/apk/arch
apk info -a <package> | grep -E "arch|depends|provides" | head
```

- `x86_64`, `aarch64_cortex-a53`, etc. ne sont pas interchangeables ;
- les modules noyau (kmod) doivent correspondre à la version/ABI du noyau ;
- les paquets de simples scripts peuvent être `any`/`noarch` et ne peuvent pas prouver un rejet d'architecture.

> Ce labo a téléchargé un `sqm-scripts` aarch64, mais il s'agit de `sqm-scripts-any` (sans binaire propre à une architecture), et `--allow-untrusted` en local l'a quand même remplacé. Cela **ne prouve pas que les contrôles d'architecture ont réussi**. Un vrai test de rejet exige un paquet contenant de l'ELF ; cette page ne le marque pas comme vérifié.

</Step>

## Couche 3 : dépendances

<Step where="router-shell" title="Lire l'arbre de dépendances et la sortie d'installation" expected="Les dépendances manquantes ont des noms de paquets précis.">

```sh
apk add <package> 2>&1 | tail -20
apk info -R <package> 2>/dev/null | head -20
apk info -e <dependency>
```

Cas courants :

- programme principal installé, `luci-app-*` manquant ;
- `kmod-*` ne correspond pas au noyau ;
- les dépendances se trouvent dans un autre dépôt ou une autre version ;
- des dépôts officiels, ImmortalWrt et iStoreOS sont mélangés.

</Step>

## Couche 4 : menu LuCI

<Step where="router-shell" title="Programme principal ≠ interface LuCI" expected="Après l'installation de luci-app, le menu et les fichiers statiques apparaissent.">

```sh
apk info -L <luci-app-name> | head -20
ls -l /usr/share/luci/menu.d/ 2>/dev/null | grep <name>
```

Dans ce labo :

- `sqm-scripts` seul : installé, mais aucun menu LuCI ;
- ajout de `luci-app-sqm` : `/usr/share/luci/menu.d/luci-app-sqm.json` et `/www/luci-static/resources/view/network/sqm.js` sont apparus ;
- suppression de `luci-app-sqm` : le fichier de menu a disparu ; la réinstallation l'a restauré.

Si le menu ne s'affiche toujours pas : videz le cache du navigateur, déconnectez-vous puis reconnectez-vous, vérifiez `luci-base`, le paquet de langue et rpcd ; ne reflashez pas en premier.

</Step>

## Couche 5 : postinst / scripts de configuration

<Step where="router-shell" title="Paquet installé mais service/configuration absents" expected="Vous savez si postinst a échoué et ce qu'il a modifié.">

```sh
logread | tail -50
apk info -L <package> | head -20
ls /etc/uci-defaults/ 2>/dev/null | tail
```

- Un postinst en échec n'annule pas forcément le paquet ;
- vérifiez `/etc/uci-defaults`, `/etc/init.d/<service>`, `/etc/config/<service>` ;
- ne forcez pas des réinstallations répétées juste pour rejouer postinst ; lisez d'abord le journal et les scripts.

</Step>

## Couche 6 : récupération

<Step where="router-shell" title="Désinstaller, restaurer les dépôts ou redémarrer plutôt que reflasher" expected="Retour à l'état précédent, ou au moins possibilité de continuer le diagnostic.">

```sh
apk del <package>
# if feeds were changed:
cp /etc/apk/repositories.d/distfeeds.list.bak.YYYY-MM-DD /etc/apk/repositories.d/distfeeds.list
apk update
reboot
```

Si le paquet casse la gestion, arrêtez d'abord le service et restaurez les sauvegardes de configuration ; le reflashage est le dernier recours.

</Step>

## Échecs courants

| Symptôme | Cause plus probable | À vérifier d'abord |
|---|---|---|
| `apk update` 404 | mauvaise version/cible/architecture/chemin du miroir | fichiers de dépôt + `curl -I` |
| Paquet introuvable | mauvais nom/dépôt/version | `apk search` |
| Téléchargé mais ne s'installe pas | architecture/dépendance/signature | `apk info -a`, sortie d'installation |
| Installé mais pas de menu | programme principal seul, pas de `luci-app-*` | `apk info -L` |
| Le menu existe mais ne s'ouvre pas | LuCI/langue/rpcd/cache | console du navigateur, `logread` |
| Erreur postinst | script/permissions/dépendance/configuration | `logread`, `/etc/uci-defaults` |
| Plus d'Internet après l'installation | le service a modifié le DNS, le pare-feu ou l'interface | arrêter le service, restaurer les sauvegardes |
