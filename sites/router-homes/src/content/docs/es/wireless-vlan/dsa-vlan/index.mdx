## DSA frente a swconfig

- Los dispositivos más antiguos suelen usar `swconfig`: `switch0`, puertos 0/1/2;
- DSA expone cada puerto como `lan1`, `lan2`, `wan`, etc.;
- El OpenWrt moderno usa **filtrado de VLAN del puente** (bridge VLAN filtering), no la sintaxis `vid/ports` de `swconfig`;
- Los nombres de los puertos varían según el dispositivo: `ip -d link show`, `ls /sys/class/net`.

## Ejemplo de bridge-vlan

Supón los puertos DSA `lan1`, `lan2`, `lan3`; convierte `lan1` en un trunk (VLAN 1 + 20 tagged) y `lan2/lan3` en acceso a la VLAN 1:

```uci
config device
    option name 'br-lan'
    option type 'bridge'
    list ports 'lan1'
    list ports 'lan2'
    list ports 'lan3'

config bridge-vlan
    option device 'br-lan'
    option vlan '1'
    list ports 'lan1:u*'
    list ports 'lan2:u*'
    list ports 'lan3:u*'

config bridge-vlan
    option device 'br-lan'
    option vlan '20'
    list ports 'lan1:t'
```

Puntos clave:

- `u*`: untagged y PVID de este puerto para la VLAN;
- `t`: tagged, transportada por un trunk;
- un puerto de acceso normalmente tiene un solo PVID untagged;
- ambos extremos de un trunk entre switches deben ser tagged y permitir las mismas VLAN;
- no mantengas la configuración antigua de `swconfig` junto a esta.

> Sustituye los nombres de puerto/puerto CPU por los de tu dispositivo; si tienes dudas, prueba en un puerto o dispositivo de repuesto.

## Aplica y verifica

```sh
uci commit network
/etc/init.d/network reload
bridge vlan show
ip -d link show br-lan
```

Verifica:

- la administración sigue llegando a LuCI/SSH;
- un cliente de acceso obtiene DHCP de la VLAN correcta;
- el par del trunk ve las VLAN tagged;
- `bridge vlan show` coincide con el diseño de PVID/tagged.

## Recuperación tras perder el acceso

1. Usa la consola/serie; no dependas solo de la red;
2. Restaura `/etc/config/network.bak.*`;
3. O devuelve temporalmente el puerto de administración a la VLAN 1 untagged;
4. Reinicia la red y confirma la administración;
5. Añade las VLAN de una en una, puerto por puerto.

## Fallos comunes

### Pérdida de acceso inmediata

- el puerto de administración pasó a tagged o tiene un PVID incorrecto;
- el par del trunk no permite la VLAN;
- se cambió de golpe el puerto CPU/uplink;
- recupera por consola; no hagas un restablecimiento de fábrica a ciegas.

### VLAN 20 inaccesible

- desajuste de tagged/untagged entre los dos extremos;
- PVID sin definir;
- no hay interfaz/DHCP/cortafuegos para esa VLAN;
- la VLAN no está creada/permitida en el switch.

### Hay dirección pero no hay internet

- la VLAN de invitados/servicio no tiene DHCP/DNS;
- la zona del cortafuegos o el reenvío no coinciden;
- falta NAT o la ruta de retorno;
- la conectividad de VLAN no es enrutamiento/NAT.

## Estado E1

- Solo documentación; no verificado en hardware/switch DSA real; no se afirma “configurado con éxito”.
- Una prueba real requiere un dispositivo DSA de varios puertos, un switch administrable, acceso por consola, una configuración de reversión y al menos dos clientes.
- Pasa a E2 solo después de registrar el modelo del dispositivo, los nombres de los puertos, la configuración del switch y la recuperación ante fallos.
