## En una línea

- **25.12+**: `apk`, los paquetes son `.apk`;
- **24.10 y anteriores**: `opkg`, los paquetes son `.ipk`;
- No se relacionan por cambio de nombre; **no renombres `.ipk` a `.apk`**;
- Tras actualizar a 25.12, reinstala los plugins desde los feeds de `apk`; la configuración se puede respaldar y restaurar.

## Comprueba en qué lado estás

```sh
cat /etc/openwrt_release
command -v apk
command -v opkg
```

Este laboratorio: 25.12.6, `apk` existe, `opkg` no.

## Comparación

| Elemento | `apk` de 25.12 | `opkg` de 24.10 |
|---|---|---|
| Formato | `.apk` | `.ipk` |
| Archivo de feeds | `/etc/apk/repositories.d/distfeeds.list` | `/etc/opkg/distfeeds.conf` |
| Actualizar índice | `apk update` | `opkg update` |
| Instalar | `apk add <pkg>` | `opkg install <pkg>` |
| Eliminar | `apk del <pkg>` | `opkg remove <pkg>` |
| Buscar | `apk search <term>` | `opkg list \| grep <term>` |
| Instalados | `apk list --installed` | `opkg list-installed` |
| Información del paquete | `apk info -a <pkg>` | `opkg info <pkg>` |
| Limpiar caché | `apk cache clean` | `opkg clean` |

## Feeds y arquitectura

25.12:

```text
https://downloads.openwrt.org/releases/25.12.6/targets/x86/64/packages/packages.adb
https://downloads.openwrt.org/releases/25.12.6/packages/x86_64/base/packages.adb
https://downloads.openwrt.org/releases/25.12.6/targets/x86/64/kmods/<kernel-hash>/packages.adb
```

24.10:

```text
src/gz openwrt_core https://downloads.openwrt.org/releases/24.10.8/targets/x86/64/packages
src/gz openwrt_base https://downloads.openwrt.org/releases/24.10.8/packages/x86_64/base
```

- `release`, `target`, `arch` y el hash de los kmods deben coincidir;
- Mezclar feeds oficiales/ImmortalWrt/iStoreOS puede romper la ABI, las firmas o los nombres;
- Un mirror de China cambia solo el host y el prefijo de la ruta; no cambies el target ni la arquitectura.

## Operaciones comunes

<Step where="router-shell" title="Instala un paquete en 25.12" expected="Actualizar, buscar, instalar y verificar usan apk.">

```sh
apk update
apk search -x sqm-scripts
apk add sqm-scripts
apk info -e sqm-scripts
apk list --installed | wc -l
```

Este laboratorio: oficial y TUNA con 11220 paquetes cada uno; se instaló `sqm-scripts 1.7.2-r1`.

</Step>

```sh

opkg list | grep sqm-scripts
opkg install sqm-scripts
opkg list-installed | grep sqm-scripts
```

Son los comandos equivalentes oficiales, **no ejecutados aquí** (sin dispositivo 24.10); no los presentes como salida medida.

## Al actualizar a 25.12

1. Respalda `/etc/config` y la lista de paquetes (ver 018);
2. Anota `opkg list-installed` de 24.10;
3. Actualiza/reinstala 25.12 (ver 019);
4. Reinstala los plugins desde los feeds de `apk`;
5. Restaura la configuración y verifica LuCI/servicios/DNS;
6. No conviertas `.ipk` en `.apk` ni copies directorios de paquetes antiguos.

El `sysupgrade` a 25.12 de este laboratorio conservó la configuración pero perdió paquetes (239→182); SQM/OpenClash necesitaron reinstalación.

## Fallos comunes

### `apk: not found`

- El firmware es 24.10 o anterior; usa `opkg`;
- “Instalar un gestor de paquetes apk” no es la solución; comprueba primero la versión.

### `opkg: not found`

- El firmware es 25.12+; usa `apk`;
- Los tutoriales o scripts antiguos que usan `opkg` no se aplican directamente.

### El `.ipk` no se instala

- 25.12 usa `.apk`;
- Renombrar no cambia el formato;
- Busca el `.apk` para la versión/target/arquitectura o recompila.

### Errores 404/firma/dependencias

- no coinciden versión/target/arquitectura/hash de los kmods;
- feeds mezclados;
- hora o certificados del sistema;
- no uses `--allow-untrusted` como solución habitual.

### No hay menú de LuCI tras actualizar

- se instaló el programa principal sin `luci-app-*`;
- no se reinstaló el plugin antiguo;
- caché del navegador/volver a iniciar sesión;
- ver 017.
